# Binary FLA fixes: technical details

_Ported from [liangforstudy/fla-viewer-fix](https://github.com/liangforstudy/fla-viewer-fix); write-up by its author._

These changes fix pre-CS5 **binary FLA** files (OLE2 / MS Compound File containers, magic `D0 CF 11 E0`). Those files are routed to `src/binary-fla-parser.ts` rather than the XFL (ZIP + XML) parser.

**Reference file:** a real Flash 8 project (720×480, 24 fps, 144 frames, 3 scene layers, 4 movie-clip symbols, one 16-bit PCM sound). It was checked against its own QuickTime export (`export.mov`) and screenshots of that export.

**Second real file:** `src/__tests__/fixtures/btnstrob.fla` (Flash MX 2004), used to confirm the fixes don't break older files. The other binary fixtures are synthetic: they are generated by scripts using the byte layouts the code assumed, so they can't validate those layouts.

**Sections 1–12** are binary-format fixes. Each was verified by rendering frames in headless Chromium (the author's local script, not included) and comparing them with the exported movie. A final check loaded the file through the real viewer UI and played it.

**Sections 13–19** are player and UI changes that apply to **all** FLA files, including CS5+ and Animate. They were verified by driving the real viewer UI with Playwright.

---

## 1. Layer record: "current", locked, hidden (not type, locked, visible)

*Files: `binary-fla-structure.ts`, `binary-timeline-decoder.ts`, `binary-fla-parser.ts`*

After the layer name (`layer_schema >= 4`) come three bytes. The code (following the fla-decoder reference) read them as `type, locked, visible`.

| Layers in the timeline | byte 0 of each layer |
|---|---|
| Flash 8 scene (`Layer 1`, `Layer 2`, `Layer 10`) | 0, 0, **1** |
| btnstrob scene (`Layer 2`, `Layer 1`) | 0, **1** |
| btnstrob `Symbol 2` | 0, **1** |
| every single-layer symbol | **1** |

**Evidence:**
- Byte 0 is set on **exactly one layer per timeline**. That is the editor's *current layer* flag, not the layer type.
- Reading it as the type (1 = guide) turned every symbol's only layer into a guide, which is never rendered. That is the white screen.
- Byte 2 is `0` for layers that clearly appear in the export, so it is a **hidden** flag (fla-decoder: 0 = visible, 1 = hidden).

**Changes:**
- The layer type now comes only from the name prefix (`Guide: `, `Folder `). Mask/masked detection from byte 0 was removed; it could not have worked on real files.
- Flash before CS5.5 always published hidden layers, so binary layers are always rendered (`visible: true`). The decoded hidden flag is still available in `BinaryFLAInfo`.

## 2. Layer walk dropped every layer after the first

*File: `binary-timeline-decoder.ts`*

After each `CPicLayer`, an "end-marker scan" moved the reader to the **last** page sentinel in the stream. This skipped all following layers (the Flash 8 scene lost 2 of its 3).

The bytes right after the first layer's record are `03 80`, a back-reference to the `CPicLayer` class: the next layer starts immediately.

**Change:** the scan is skipped when `ArchiveReader.peekBackrefName()` (new, in `binary-shape-decoder.ts`) says the next object is a `CPicLayer`.

## 3. Content duplicated onto every layer

*File: `binary-fla-parser.ts` (`buildAttributedLayers`)*

Each layer bucketed *all* of the stream's shapes and instances by its own keyframe byte ranges. It then put everything outside those ranges ("orphans") on its first frame, so other layers' content was copied onto it.

**Change:** content only counts as an orphan when it falls outside **every** layer's keyframes, and orphans are placed once, on the first drawn layer (a guide or folder layer is skipped, since it is never rendered).

## 4. Layer stacking order

*File: `binary-fla-parser.ts` (`toTopFirst`)*

Binary timelines store layers **bottom-first**; the viewer, like XFL, expects `layers[0]` to be the top layer.

**Evidence:** in the Flash 8 file, the first-stored layer holds the table, which the export draws *behind* the food on the second layer (the burger's bottom bun overlaps the table edge).

**Change:** layers are reversed, and reference-layer indices are remapped to match.

## 5. Symbol reference of placed instances

*File: `binary-instance-decoder.ts`*

The `u32` read as `media_ref` (fla-decoder reads the same one) was always `1` in both real files. In these Flash 8+ records the real reference follows:

```
u32 1 | u8×3 0 | s32 -1 | FF FE FF <u8 len> <UTF-16 name> | u32 media_ref
```

**Evidence:**
- Flash 8 file: the refs decode to 1, 4, 5, 6 (table, EXPLOTION, chicken, burger). Each matches its placement position in the export.
- btnstrob: the stage sprite now resolves to `mvc BtnStrobe` (a movie clip) instead of `Symbol 1`, a *graphic*, which a `CPicSprite` placement cannot reference.

The new layout is only used when the `FF FE FF` string is present, so older records keep the old reading.

## 6. Edge coordinate precision (Flash 8+)

*File: `binary-shape-decoder.ts` (`edgeUnitsPerPx`)*

Edges were converted at 2560 units/px (20 twips × 128). In the Flash 8 file:
- every shape's edge centre was exactly **2×** its compensating shape offset (e.g. chicken 628.8 = 2 × 314.4);
- shapes only matched the export's size and position when halved.

All of that file's shapes have `shape_schema 3`; btnstrob's have `shape_schema 2`.

**Change:** `shape_schema > 2` (the same Flash 8 gate as stroke caps) uses **5120 units/px**; older shapes keep 2560.

## 7. Stage size

*File: `binary-fla-parser.ts` (`extractStageRect`)*

The width and height came from the HTML publish-setting strings, which were stale in both real files (550×400). The real stage is a twips rectangle `{0, right, 0, bottom}` (4 × `s32`) sitting exactly **53 bytes before** the background-colour record in both files:

| File | Stage |
|---|---|
| Flash 8 file | 720×480 (matches the export) |
| btnstrob | 600×300 (its sprite sits at the exact centre, 300,150) |

The publish settings are now only a fallback.

## 8. Edge style-change order: LINE, FILL1, FILL0

*File: `binary-shape-decoder.ts` (`readEdgeStream`)*

Style-change records carry three indices; they were read as `fill0, fill1, line`.

**Evidence:**
- The first index is 0 in every stroke-less shape, and 1 in btnstrob's single 1-fill/1-stroke shape, so it is the **line** style.
- The old order dropped one fill of every two-fill shape (the table's shading, the chicken's bone) and invented strokes on shapes with no line styles.
- The left/right fill order was confirmed by matching renders to the export.

## 9. Gradient fills in `shape_data_schema >= 5`

*File: `binary-shape-decoder.ts` (`readFillStyle`)*

The burger symbol's red→yellow linear gradient has **5 extra bytes** (all zero) between the gradient type and the stops. These are presumably focal point, spread and interpolation, which Flash 8 introduced.

Not reading them misaligned the rest of the shape, and the whole burger was discarded. The four solid fills that follow (patty, lettuce, cheese, tomato) now decode at the right offsets.

## 10. Exact contour stitching for binary shapes

*Files: `renderer.ts`, `types.ts` (`Shape.exactEdges`), `binary-shape-decoder.ts`*

The renderer joins fill-edge endpoints up to 8 px apart; XFL needs that tolerance. The taco's crust is dozens of separate 1–3 px islands of one fill. With 8 px tolerance, 136 jumps threaded them into one polygon, and the auto-close line drew a large yellow wedge across the taco.

Binary edges have exact integer endpoints: every vertex of that shape balances in-edges against out-edges. Binary shapes therefore set `exactEdges`, and are stitched at a tolerance of 1e-6. XFL rendering is unchanged.

## 11. Motion tweens

*Files: `binary-timeline-decoder.ts`, `binary-fla-parser.ts`*

In the `CPicFrame` tail, `field_188` bit 0 marks a classic **motion tween** to the next keyframe:

| Value | Keyframes |
|---|---|
| `0x1E01` | the three explosion scale-up keyframes (tiny → full size), plus the full-size keyframes right after each |
| `0x0600` | every static keyframe |

`field_190` is treated as the ease (−100..100); only 0 was observed, and out-of-range values are ignored. The frames get `tweenType: 'motion'`, and the existing renderer interpolates the instance matrix toward the matching symbol in the next keyframe.

## 12. Sound

*Files: `binary-fla-parser.ts` (`extractSounds`), `binary-timeline-decoder.ts`, `fla-parser.ts` (`loadBinarySounds`)*

Sound was not decoded for binary files at all.

**`CMediaSound` records (in `Contents`):**
- `u8 len` + UTF-16 stream name (`Media N`), then the display name (`FF FE FF` string);
- a footer `00 0A <format> 00 <u32 sampleCount>`.

**The format byte** is laid out like the SWF sound header: bit 0 stereo, bit 1 16-bit, bits 2–3 rate index (5.5k / 11k / 22k / 44.1 kHz). The Flash 8 file's `0x0E` = 44.1 kHz 16-bit mono; its `Media 1` stream is exactly `sampleCount × 2` bytes (528,384 = 5.99 s, matching the 6 s export).

**Codec:** the stream is sniffed as MP3 (`FF Ex` / `ID3`) or taken as raw PCM when its length matches the footer. Anything else (ADPCM, Nellymoser) is warned about and skipped, not guessed at.

**Frame link:** `CPicFrame` has a `u16` sound reference (`fs > 4`) that was read and discarded. N means `Media N`; it is set only on the Flash 8 file's sound-only layer (one keyframe spanning all 144 frames). Keyframes now carry `soundRef`, and the frame gets `sound: { sync: 'event' }`. The sync mode is **not decoded**; `event` is Flash's default.

## 13. Event sounds were never played (all FLA files)

*Files: `player.ts`, `video-exporter.ts`*

Both only scheduled `sync === 'stream'`. The XFL parser defaults a missing `soundSync` to `event`, so event sounds were silent everywhere, including in exports.

**Change:** `event` and `start` sounds are now scheduled too. They stay active until the sound ends, even past their keyframe; `stop` is still ignored.

## 14. Play/Pause button ignored clicks on its icon (all FLA files)

*File: `main.ts` (`updateUI`)*

`updateUI` runs on every rendered frame and rewrote `playBtn.innerHTML` each time. A `click` only fires when `mousedown` and `mouseup` land on the same element, and during playback the SVG under the cursor was replaced between the two, so clicks on the icon were lost. Clicks on the button's padding (its own element) still worked.

**Change:** the icon is only replaced when the play/pause state changes (tracked in `playBtn.dataset.icon`).

**Verified:** Playwright press-and-release (120 ms) on the icon centre during playback now pauses.

## 15. Timeline scrubbing (all FLA files)

*Files: `main.ts`, `index.html`*

The timeline only had a `click` listener on a 4 px-tall bar, so dragging did nothing until release, and the bar was hard to hit.

**Changes:**
- **Pointer events:** `pointerdown`/`pointermove`/`pointerup` with pointer capture, so the playhead follows a drag.
- **Pause while dragging:** playback pauses during the drag and resumes on release. Seeking a playing timeline restarts the audio on every move.
- **Bigger hit area:** an invisible `::before` area makes the grab zone 20 px tall; the visible bar is unchanged.

**Verified:** dragging from 10% to 90% steps through frames 15 → 43 → 72 → 101 → 129, including when grabbed 7 px above the bar.

## 16. Reset view by double-click (all FLA files)

*File: `main.ts`*

Pan and zoom could already be reset with the `0` key, but the Reset View button only exists in the mobile controls. A `dblclick` on the canvas now calls `player.resetView()`. Single clicks on the canvas are only used by debug mode, so nothing conflicts.

## 17. Duplicate audio after loading another file (all FLA files)

*Files: `player.ts` (`destroy`), `main.ts`*

Each load created a new `FLAPlayer` without stopping the previous one. The old player's animation loop and sound kept running, so a second load (or loading the sample again) played two soundtracks, and pausing only affected the new player. Reported on iPhone.

**Change:** `FLAPlayer.destroy()` pauses, detaches the state callback and closes the player's `AudioContext`; `loadFile` calls it before creating the new player.

**Verified:** Playwright, iPhone 13 emulation. After re-loading while playing, exactly one audio source is live, the old context is closed, and one tap on pause silences it.

## 18. iOS double-tap zoom (all FLA files)

*File: `index.html`*

Safari zooms the page on a quick double tap, which fast taps on Play/Pause triggered. `html { touch-action: manipulation; }` disables double-tap zoom but keeps pinch zoom; `touch-action` combines down the tree, so it covers every element, and the canvas keeps its own `none` for panning.

## 19. Collapsible mobile zoom/pan panel (all FLA files)

*Files: `index.html`, `main.ts`*

On phones the fixed zoom/pan panel covered part of the stage and couldn't be hidden. A toggle button at the bottom of the panel collapses it to just that button. The panel is anchored by its bottom edge, so the toggle stays in place (±1 px). The state is stored in `localStorage` (`mobileControlsCollapsed`), with storage errors ignored, and `aria-expanded`/labels are updated.

## Which Flash version saved the reference file?

The binary format doesn't store the authoring version directly, but the publish settings in the `Contents` stream give it away:

| File | `Vector::Version` (publish target) | `PublishHtmlProperties::VersionInfo` (players the program knew) | Saved by |
|---|---|---|---|
| `project.fla` | 8 | `8,0,0,0; 7,0,0,0; …` | **Flash 8** |
| `btnstrob.fla` | 7 | `7,0,0,0; 6,0,0,0; …` | Flash MX 2004 (Flash 7) |

`VersionInfo` is the list of Flash Player versions the authoring program offers for HTML version detection, so it stops at the newest player that program knew. A CS3 or CS4 file would list 9 and 10. The file's creator also confirmed it was Flash 8.

The Flash 8-specific findings (§6 edge precision, §9 gradient bytes) fit this: Flash 8 introduced the newer shape records.

## Tests

Tests that encoded the old, disproven layouts were updated, and each change is justified above:

- `binary-fla-structure.test.ts`, `binary-timeline-decoder.test.ts`: layer byte semantics (§1).
- `binary-fla-parser.test.ts`: hidden layers render (§1) and top-first order (§4). The synthetic `binary-layers.fla` fixture was regenerated after updating `scripts/gen-binary-fla-layers.mjs` to the corrected byte layout.
- `binary-instance-decoder.test.ts`: btnstrob's sprite references `mvc BtnStrobe` (§5).
- `binary-shape-decoder.test.ts`: style-change order (§8).

## Known gaps

- **Mask/masked layers** in binary files: the real layer-type field hasn't been identified (possibly the `layer_mode` byte).
- **Sound sync mode, in/out points and loops** in binary frames aren't decoded.
- **Frame labels, shape tweens and per-target / custom eases** in binary files aren't decoded.
- Several layouts (§6, §9, §11, §12) were confirmed on one real Flash 8 file (see the version check below). Test them on more real files before relying on them.

## Next: sound sync, then mask layers

Neither is documented in the fla-decoder reference. Its notes only confirm that the frame's sound reference is a `u16` and that an unconditional `layer_mode` byte exists, with no meanings for either. The current file has one sound and no masks, so decoding these would be guesswork. They will be decoded the same way as the fixes above: by comparing bytes in small test files whose settings are known.

Test files still to be made, in Flash 8 (like `project.fla`) or any version up to CS4, saved in a pre-CS5 binary format (not CS5/XFL), with each layer named after its setting:

**`sound-sync.fla`**: one short sound; each layer has a keyframe on frame 1 using it.

| Layer name | Sync | Repeat/Loop |
|---|---|---|
| `event` | Event | Repeat 1 |
| `start` | Start | Repeat 1 |
| `stop` | Stop | Repeat 1 |
| `stream` | Stream | Repeat 1 |

Likely candidates: the unread `fs > 5` entry table and the `fs > 6` fields in `consumeCPicFrame` (`binary-timeline-decoder.ts`).

**`masks.fla`**, layers top to bottom, plus a stage screenshot for comparison:

| Layer name | Layer type | Content |

Likely candidates: the `layer_mode` byte and the parent `ReadObject` after it in the layer tail. The walker currently throws on a non-null parent, which would reject a masked layer's timeline.
